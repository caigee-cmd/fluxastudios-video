# Fluxa Studios 后台配置、当前状态与发布原则

本文面向站点管理员，说明本仓库镜像现状、在网站上改配置的入口、当前已落地的产品状态，以及如何更新代码或只更新前端。本文可单独公开，不包含密钥、服务器登录方式或机器路径。

更细的用户可见积分文案口径见 [fluxa-credit-explanation.md](./fluxa-credit-explanation.md)。镜像发布与部署的内部约束另见 [fluxa-studios-ops.md](./fluxa-studios-ops.md)；公开转发时请优先使用本文，不要把含有机器路径或环境细节的段落一并拷贝出去。

| 服务 | 镜像仓库 |

## 2. 生产改配置入口

改价格、时长、清晰度展示、套餐和支付开关，都在本站管理后台完成，不需要登录服务器。

| 要做什么 | 在哪里点 |
| --- | --- |
| 编辑系统渠道、协议、模型上下架 | [渠道与模型](https://fluxastudios.com/admin/channels) |
| 编辑某个模型的能力、价格档、时长和清晰度展示 | [渠道模型列表](https://fluxastudios.com/admin/channels?view=models) |
| 上架或启停充值套餐、启停支付渠道 | [支付充值](https://fluxastudios.com/admin/payments) |
| 启停积分、前台逻辑模型目录、工作台等功能 | [功能开放](https://fluxastudios.com/admin/settings/features) |
| 查看账务、调账、人工发放积分 | 积分运营（账务工具，不是上架页） |

用户侧对应入口：

- 创作页：选择系统渠道已发布的模型，调节时长等参数，提交前会看到服务端询价
- 设置里的模型选择：同一套系统渠道目录
- 钱包 / 充值中心：展示已上架的积分套餐；若支付渠道未启用，用户无法完成在线付款

### 改价格、时长和清晰度时要注意

- **空的 resolutions 会导致模型从目录消失。** 系统渠道目录在补默认清晰度时，如果能力里没有可用的分辨率选项，模型会被整条省略，前台选不到。需要保留至少一个展示用分辨率，并设置默认值。
- **0 元有效价等于免费。** 不要把「先上架、回头再定价」写成单价 0 且启用；未定价应保持价格未配置，让选择器不可见。
- **没有有效价格档时，选择器不可见，创建任务也会失败。** 上架前必须有启用且已配置的价格。
- 当前 MiniMax H3 使用的协议是本站后台中的 **OpenAI Videos / Sora**（协议 id：`newapi`）。该协议**不会把 `resolution` 字段发给上游**，清晰度通过可选的 `size` 表达。因此后台里的 **768P 是展示和默认标签**，用来说明「不额外传尺寸时按 768P 理解」，并不是向下游再发一次分辨率参数。
- **不要随意打开画面比例。** 若配置了比例，`newapi` 可能把比例值当作 `size` 发出，而该协议的 `size` 应是像素尺寸（例如 `1280x720`），不是 `16:9` 这种比值。当前 H3 刻意不配画面比例，避免发出不合适的 `size`。
- 改按秒计费时，单价是「每秒多少积分」，总价随用户选择的秒数变化。不要继续用按次固定价去覆盖所有时长。
- 成本价不要填未核实的数字；没有实测就保持未配置。

### 改套餐、支付和模型上下架

- 上架人民币积分套餐时，若要与默认「1 元 = 1 积分」一致，到账微积分须等于 `金额分 * 10,000`。促销包可以不同，但展示必须以该套餐的到账数为准。口径见 [积分说明](./fluxa-credit-explanation.md)。
- 启停支付渠道在支付充值页。渠道未启用时，即使用户能看到套餐，也不能在线付款。
- 启停模型在渠道模型列表。关闭后前台不应再选到它。只停价格或只停模型时，确认目录和创建路径都会一起失效，避免「看得见却生成失败」或「生成了却没计价」。

## 4. 如何更新代码与只更新前端

常规路径：

1. 在 GitHub 本仓库改代码或文档，从 `main` 拉出分支并开 Pull Request。
2. 等待 **Quality checks** 通过后再合并。
3. 合并 `main` 后，等待 **Publish Fluxa Studios images** 为该提交构建并推送 `sha-<提交>` 镜像。
4. 确认镜像已发布，再在生产部署配置里更新对应镜像标签。发布不等于自动部署。

只更新前端时：

- 只改部署配置中的 `CANVAS_WEB_IMAGE`，指向已发布的 `ghcr.io/caigee-cmd/fluxastudios-web:sha-...`。
- 然后只用 Compose 针对 **web** 服务执行 `up -d --no-deps --force-recreate`。这样不会顺便重建 backend。
- **不要**把会同时重建 backend、跑数据库迁移的总部署脚本当成「只更新 web」的默认操作。
- **不要**把含密钥的整份 `.env` 贴进工单、聊天或仓库。需要改镜像标签时，只改那一个变量。

安全约束请概括遵守：官方宿主更新器保持屏蔽，不要用它覆盖自建镜像；对外由站点反向代理终止 HTTPS，web 进程只监听本机回环，不要把应用端口直接暴露到公网。后端重建有自己的迁移与附属服务顺序，不属于 web-only 操作。

回滚前端时，把 `CANVAS_WEB_IMAGE` 改回上一枚已验证的 web SHA 标签，同样只重建 web。不要把后端退到不支持当前 schema 99 的镜像。

## 5. 已知限制与不要做的事

- **不要开放 16–30 秒。** 目前只对等验证了 4 秒与 15 秒（以及默认 6 秒价）。官方能力口径也以 4–15 秒整数为准。
- **不要在未验证时增加 2K 或其他清晰度档，或把 768P 理解成会下发的协议字段。** 当前没有测过其他清晰度；展示标签与实际上游字段不是一回事。
- **不要在文档或操作里教人随便打开邮件发送或公开注册。** 注册关闭是有意设置；要开放必须单独授权，并先核对协议、验证与发信是否真正就绪。
- 不要把未询价的界面空值显示成 0 积分免费；不要把未核实的成本价写进后台。
- 不要在公开文档、工单或仓库中粘贴 API Key、支付密钥、令牌、整份环境文件或机器登录信息。
